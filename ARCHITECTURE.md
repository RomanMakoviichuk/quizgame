# Архітектура

Хоррор-вікторина «Хто є хто!» — гра для компанії: великий екран (ТВ)
+ телефони гравців, зв'язок через Socket.IO у реальному часі.

```
┌─────────────┐        websocket         ┌──────────────────┐        websocket        ┌─────────────┐
│  Телефон 1  │ ───────────────────────▶ │                  │ ◀────────────────────── │   Дисплей   │
│  Телефон 2  │ ───────────────────────▶ │  Socket.IO :3001 │ ──────────────────────▶ │  (ТВ/екран) │
│   ...  (8)  │                          │   in-memory Map  │                         │  відео/звук │
└─────────────┘                          └──────────────────┘                         └─────────────┘
      React (client/)                      Node + Express (server/)                      React (client/)
```

Один React-бандл (`client/src/App.js`) працює у двох ролях, які визначаються
`isMobile()` (ширина ≤ 768px або мобільний user-agent):

| Роль | Що робить |
|------|-----------|
| **Дисплей** (`createRoom`, `socket.isDisplay`) | Показує код кімнати, програє **весь звук і відео**, керує переходами фаз через події `*Done` |
| **Гравець** (`joinRoom`) | Вводить код, відповідає на питання, грає в міні-ігри. **Повністю без звуку.** Перший, хто зайшов, — `isAdmin` |
| **Сервер** | Тримає весь стан у пам'яті, рахує бали й життя, читає питання з JSON, вирішує міні-ігри. Рестарт = всі кімнати втрачені |

**Звук.** Усі `<audio>`-елементи в `App.js` рендеряться лише коли `!isMobile()`
(тобто на дисплеї). Плюс явні перевірки `if (isMobile()) return` у обробниках
`answerBeep` та звуку результату раунду. Відео з озвучкою (`IntroScene`,
`TrueFalseMinigame` display-режим, `TrueFalseAftermath`, фонові відео) рендеряться
теж лише на дисплеї. На телефоні — тиша.

## Сервер (`server/`)

Розбитий на модулі з чіткою відповідальністю. Ніяких глобальних змінних —
`io` передається через фабрики.

| Файл | Відповідальність |
|------|------------------|
| `server.js` | Тільки bootstrap: express, http, io, статика, `listen` |
| `config.js` | Усі константи й env (порт, таймери, `TOTAL_ROUNDS`, `LIVES_PER_PLAYER`, `GAME_STATE`) |
| `rooms.js` | `rooms` Map, фабрика кімнати, `addPlayer`, серіалізація гравця для дроту, очищення таймерів |
| `questions.js` | Колоди питань: `roundN.json` → фільтр за складністю → перемішана колода (crypto) → одне питання за гру |
| `phases.js` | **Машина фаз** — фабрика `(io) => { ... }`. Уся ігрова логіка тут |
| `handlers.js` | Прив'язка Socket.IO-подій. Тільки валідація сокета + виклик `phases` |
| `minigames/index.js` | **Реєстр міні-ігор**: `selectForRound(roundIndex)` вирішує, яка міні-гра після якого раунду |
| `minigames/trueFalse.js` | Правила «Правда/Брехня»: хто змагається і хто втрачає життя (чисті функції) |

### Машина фаз

**9 раундів вікторини**, потім **фінальна битва**.

```
WAITING
  │  startIntro (адмін) → showIntro → IntroScene → rulesmovie (дисплей)
  │  introEnded / startGame → phases.startGame()
  ▼
QUESTION_ANNOUNCE  emit "questionAnnounce"
  │  раунди 1-2: власне відео-інтро (introround1/2.mp4)
  │  раунди 3-9: напис «РАУНД N» (компонент RoundIntro) ~3.2с
  │  дисплей: "questionAnnounceDone" → emitQuestionPlay()
  ▼
QUESTION_PLAY  emit "questionPlay" (текст + аудіо + відео)
  │  раунд 1: фіксований таймер 6с → startAnswerPhase()
  │  раунди 2-9: "questionPlayDone" → startAnswerPhase()
  ▼
ANSWER_PHASE  emit "answerPhase" + таймер 15с
  │  усі відповіли АБО таймаут → checkAnswers() → emitScores()
  ▼
SCORES  emit "scores"; armMinigame() створює контест, якщо ≥2 гравці помилились
  │  дисплей: "scoresDone" → handleScoresDone():
  │     • міні-гра очікує   → startMinigame()  → "trueFalseStart"
  │     • міні-гра зіграна  → чекаємо "trueFalseResultsSceneDone" → знімаємо життя
  │     • міні-гри немає    → advanceRound()
  ▼
… цикл × 9 раундів
  ▼
FINAL_BATTLE  emit "finalBattle" (інтро) → фінальна гонка, див. розділ «Фінальна гонка»
  │  дисплей: "finalBattleDone" АБО серверний fallback-таймер → finishGame()
  ▼
FINISHED  emit "gameFinished"
```

### Міні-ігри після кожного раунду

Після **будь-якого** раунду `emitScores()` → `armMinigame()`:
`minigames.selectForRound(roundIndex, room.minigameHistory)` повертає **список
кандидатів** у порядку пріоритету; `phases.js` запускає першу, чий `buildContest()`
поверне контест (тобто чия умова спрацювала), і дописує її id у
`room.minigameHistory` (скидається на старті гри). Якщо жодна — міні-гри цього
раунду немає.

**8 міні-ігор, без повторів** (`minigames/index.js` `MINIGAMES`). Порядок кандидатів:

1. **RARE**-ігри, які ще не грали (зараз — Перетягни канат: потрібна парна кількість
   тих, хто помилився). Вони йдуть першими, тож запускаються щойно умова вперше справдилась.
2. Решта ще не зіграних — **у випадковому порядку**.
Уже зіграні **не повторюються**, поки є незіграні: якщо жодна з незіграних цього раунду не може
   стартувати (наприклад, канату потрібна парна кількість), міні-гри цього раунду немає.
   Коли зіграно всі 8, починається нове коло (випадково, але не гра попереднього раунду).


| Міні-гра | Модуль | Тригер | Хто грає | Втрата життя |
|----------|--------|--------|----------|--------------|
| **Правда/Брехня** | `trueFalse.js` | ≥2 помилились | тільки ті, хто помилився | всі з мін. балом (нічия → кілька) |
| **Тупоматика** | `mathRush.js` | ≥1 помилився | **усі** | один — найнижчий бал (тайбрейк: темп → точність → час → id) |
| **Камінь-Ножиці-Папір-Паяльник-Янукович** (5 варіантів: кожен б'є двох; один б'є всіх — тільки він далі; кругова бійка — найменше очок вибуває) | `rps.js` | ≥2 помилились | тільки ті, хто помилився | один — хто вилетів **останнім** |
| **Гаряча бомба** (ланцюжок назв тварин) | `hotBomb.js` + `hotBombWords.js` | ≥1 помилився | **усі живі** | кожен, у кого вибухнула бомба (він вибуває з цього раунду міні-гри, тож максимум −1 життя на гравця) |
| **Перетягни канат** (серія до 2 перемог) | `tugOfWar.js` | помилились 2/4/6/8 | тільки ті, хто помилився (дві рівні команди) | уся команда, що програла серію; нічия — ніхто; **дві нічиї поспіль** — усі учасники |
| **Вгадай мелодію** (5 раундів, бали за швидкість) | `nameThatTune.js` + `data/tunes.json` | ≥1 помилився | **усі живі** | після 5 раундів: 4+ гравців — 3 найменші суми, 3 або 2 — один; нічия на межі — усі з цим рахунком; усі рівні — ніхто |
| **Меморі: кольоровий хаос** (порядок або кольори) | `memory.js` + `data/memoryItems.json` | ≥2 помилились | тільки ті, хто помилився | найменший бал (усі однакові — ніхто); найкращий одноосібно +1 бал |
| **Серед нас: КРИСА** (таємне голосування) | `rat.js` | ≥2 помилились | тільки ті, хто помилився | ніхто не підмутив — ніхто; рівно один — усі, крім нього (він +1 бал); кілька (не всі) — тільки ті, хто підмутив; усі підмутили — усі |

**Вгадай мелодію** (server-authoritative): каталог — аудіофайли з
`client/public/assets/minigames/name-that-tune/songs` (читаються на старті гри; `background.mp3` поруч із папкою — фон), назви з
`server/data/tunes.json` або з імені «Виконавець - Назва». Сервер вибирає 5 різних
пісень (+2 запасні), 4 варіанти з унікальними назвами в однаковому для всіх
порядку і правильну відповідь. Уривок грає **тільки телевізор** з непрозорого
`/tune/<токен>` (папка з піснями через сервер закрита); телевізор шле
`minigameDisplayEvent` `tune:ready` / `tune:audioFail` — збійний уривок
замінюється запасним, інакше раунд скасовується без штрафу. Відповідь одна,
приймається між `startAt` і `endAt` серверного часу; порядок правильних — за
часом отримання сервером; бали `CONFIG.POINTS` (100/80/60/50/40/30/20/10).
Таймінги: `TUNE_INTRO_MS` (12с), `TUNE_ANNOUNCE_MS` (3с), `TUNE_PLAY_MS` (15с),
`TUNE_RESULT_MS` (4.5с). Як додати пісню — `Name That Tune/README.md`.

**Меморі: кольоровий хаос** (server-authoritative): сервер один раз на раунд
бере 5 різних предметів із `server/data/memoryItems.json` (`MEMORY_COUNT`),
випадковий порядок, випадковий колір кожному (синій/червоний/зелений/жовтий) і
режим «порядок» або «кольори» 50/50 (режим таємний до фази відповіді).
Таймінги: `MEMORY_PREP_MS` (30с: правила + 3-2-1), `MEMORY_SHOW_MS` (20с —
запам'ятати), `MEMORY_ANSWER_MS` (15с). Рівні за раундом вікторини: 1–3 — 2 кольори,
4–6 — 3, 7–9 — 4 (палітра випадкова). Кольоровий ряд іде **тільки на дисплей**
(`ctx.emitDisplay`), телефони отримують лише завдання. Телефон постійно шле
поточну відповідь, `final` її блокує; по завершенні рахується остання. 1 бал за
позицію/колір. Новий предмет: картинка в `client/public/assets/minigames/memory/`
+ рядок у реєстрі (+ `python server/tools/build_memory_items.py` для легкої копії)
— див. `items/README.md`.

**Серед нас: КРИСА** (server-authoritative): кожен учасник таємно обирає
«ПІДМУТИТИ ЗАРЯДКУ» (`steal`) або «НЕ ЧІПАТИ» (`keep`) за 30с серверного
часу (`RAT_VOTE_MS`; підготовка `RAT_PREP_MS`, 20с). Голос остаточний; до кінця
вікна назовні йде лише кількість тих, хто вже вирішив (`rat:progress`), власний
вибір повертається тільки автору (`rat:ack`). Не проголосував або вийшов без
голосу = «НЕ ЧІПАТИ» (рахується окремо як `abstainIds`); множина учасників T
фіксується при старті і не змінюється. Результат обчислюється один раз при
закритті й заморожується. Графіка: `web/classroom.webp` (клас без зарядки) і `web/charger.webp` (зарядка окремо) — зроблені з
`backgroundwithoutcharge.webp` і `charge.png`; дошку й годинник малює CSS/SVG. Звуки: `background.mp3` (фон на ТВ),
`1.mp3`…`8.mp3` — k-те рішення грає `k.mp3` (однаково для будь-якого вибору).

**Тупоматика** (server-authoritative): сервер генерує спільний пул рівнянь
(`+`/`-`, 4 варіанти, один правильний), валідує кожну відповідь, веде бали й
годинник. Правильна відповідь +1, помилка −1 (рахунок може піти в мінус). Гравці, що помилились у питанні, отримують шанс урятуватись — якщо
хтось із них не найгірший у Тупоматиці, життя втрачає справжній аутсайдер.
Числа й таймінги налаштовуються env: `MATH_RUSH_MIN`, `MATH_RUSH_MAX`,
`MATH_RUSH_PLAY_MS` (вікно гри, 30с), `MATH_RUSH_PREP_MS` (час на читання
інструкції + 3-2-1, зараз **15с** — цифра показується лише останні 3с).

**Гаряча бомба** (server-authoritative): бомба в одного гравця; він пише назву
тварини на останню значущу літеру попереднього слова (Ь, Й, И, апостроф
пропускаються; якщо на літеру не лишилось слів — береться попередня, далі
випадкова), потім обирає, кому передати (можна заздалегідь). Два годинники на
сервері: раунд 2 хв (`HOT_BOMB_PLAY_MS`) і запал 15с на гравця
(`HOT_BOMB_FUSE_MIN_MS` / `HOT_BOMB_FUSE_MAX_MS`), що перезапускається при кожній
передачі. Якщо за 2 хв ніхто не вибухнув — бомба вибухає в того, у кого вона в
кінці (раунд завжди коштує комусь життя). Кожен хід несе `seq` бомби — застарілі/повторні події
відкидаються. Вибух → гравець вибуває з міні-гри, бомба стартує з новим
словом у випадкового живого. Кінець раунду — без додаткового вибуху. Гравець,
що вийшов з кімнати, передає бомбу без втрати життя (`onPlayerLeft`).
Словник — `server/data/ukrainianAnimals.json` (676 назв, див. `server/data/README.md`).


**Камінь-Ножиці-Папір** (server-authoritative): вибори приховані до розкриття,
таймаут → випадковий вибір. Розкриття раунду (`resolveRoundOutcome`):
1 різний вибір або всі 3 → нічия, переграємо; 2 різних → далі йдуть тільки ті,
хто обрав виграшний варіант. Проміжні вибулі **життя не втрачають** — тільки
останній вибулий (той раунд, що залишив 1 гравця). Нічия останнього раунду →
тайбрейк: хто не обрав (авто) → хто обрав пізніше → більший id. env:
`RPS_CHOICE_MS` (вибір за раунд), `RPS_REVEAL_MS`, `RPS_PREP_MS` (інструкція + 3-2-1, зараз **11с**).

> Інструкція кожної нової міні-гри показується на екрані під час `PREP_MS`;
> велика цифра відліку з'являється лише коли лишається ≤ 3 с. Щоб змінити час на
> читання — `MATH_RUSH_PREP_MS` / `RPS_PREP_MS` (мс) або константа `PREP_MS` у модулі.

**Інтерфейс модуля міні-гри** (усі поля крім `ID`/`TOTAL_DURATION_MS`/`buildContest`/`resolveLosers` — опційні):

```
ID, TOTAL_DURATION_MS                        // серверний hard-stop
buildContest({players, correctIndex, roundIndex}) -> contest | null
onStart(mg, ctx)                             // підготувати стан
onSync(mg, serverNowTs, ctx)                 // спільний годинник прийшов — старт геймплею
onClientEvent(mg, playerId, name, data, ctx) // подія від гравця (minigameEvent)
resolveLosers(mg) -> playerId[]              // хто втрачає життя
buildResults(mg) -> {...}                    // додаткові поля у trueFalseResults
clientScored: true                           // (тільки Правда/Брехня) телефон рахує сам
```
`ctx` = `{ now, players, emitAll, emitPlayer, setTimer, scheduleResolve, resolveNow }`.

**Щоб додати ще одну:** файл у `server/minigames/` + рядок у `MINIGAMES` (`minigames/index.js`;
якщо тригер рідкісний — `RARE = true` у модулі, щоб гра мала пріоритет, поки не зіграна);
компонент у `client/src/components/` + рядок у `MINIGAME_COMPONENTS`
(`client/src/components/MinigameHost.jsx`).

### Відео оголошення раундів

`client/public/assets/rounds/announce/round-N/` — кліпи «РАУНД N». `media.announceVideo(room, N)`
бере наступний файл папки по черзі (між іграми, стан у `server/data/round-announce.json`),
один раз на гру; URL іде в `questionAnnounce.introVideo`. Порожня папка → `null` → напис
`RoundIntro`. Фон під питанням — випадковий кліп з `questions/video/questions/`
(`media.questionVideo`, без повторів у грі) у `questionAnnounce.questionVideo`; порожньо → `main.mp4`.
Папки віддаються сервером напряму (`express.static`), тож нові кліпи працюють
без перезбирання. Усі ці кліпи (оголошення і серія результатів) показує `components/CinemaClip.jsx`: поява з
чорного зі звуком, затухання за ~0,9 с до кінця, пауза ~0,35 с, `onDone` один раз; битий файл,
заблокований autoplay чи завислий кліп не зупиняють гру (страховий таймер на `gameClock`).
Подробиці — `questions/video/README.md`.

### Події Socket.IO

| Подія | Напрям | Призначення |
|-------|--------|-------------|
| `createRoom` / `joinRoom` | → срв (з callback) | Створити / зайти в кімнату |
| `startIntro` / `startGame` / `introEnded` | адмін/дисплей → срв | Запуск гри |
| `skipIntro` | адмін → срв → усі | Пропустити кіно-інтро: дисплей одразу переходить до відео правил |
| `skipRules` / `rulesStarted` | обидва боки | Керування відео правил |
| `questionAnnounceDone` / `questionPlayDone` / `scoresDone` | дисплей → срв | Рукостискання фаз (відео завершилось) |
| `answer` | телефон → срв | `{ answerIndex }` |
| `trueFalseSync` | дисплей ↔ срв | Спільний годинник для будь-якої міні-гри |
| `trueFalseScore` | телефон → срв | Фінальний бал (тільки Правда/Брехня) |
| `minigameEvent` | телефон → срв | `{ name, data }` — дії в server-authoritative міні-грах (`mathRush:answer`, `rps:choose`) |
| `trueFalseResultsSceneDone` | дисплей → срв | Сцена підсумку завершилась → зняти життя |
| `finalBattleIntroDone` | дисплей → срв | Інтро фіналу (назва, правила, 3-2-1) завершилось → перше питання |
| `finalAnswer` | телефон → срв | `{ answerIndex }` — тільки індекс; приймається перша відповідь |
| `finalQuestion` `finalAnswerAck` `finalAnswerProgress` `finalStepResult` | срв → (усі / гравцю) | Кроки гонки |
| `trueFalseStart` `trueFalseResults` | срв → усі | Старт / підсумок міні-гри (payload має `minigameId`) |

### Сховище — `server/content/`

| Файл | Роль |
|------|------|
| `store.js` | Уся робота з БД питань. Один JSON-файл `content.json` з атомарним записом (temp-файл + rename). Переживає рестарт. Фабрика `createStore(path)` + дефолтний singleton на `CONTENT_FILE`. |

**Модель даних** (розрахована на розширення):

```
Category { id, name, slug, description, icon, isActive, createdAt, updatedAt }
Question { id, categoryId, type:"single", text, difficulty|null, isActive, order,
           answers:[{ id, text, isCorrect }],          // рівно 4, рівно 1 правильна

```

| Файл | Роль |

`GET /stats`, CRUD `/categories` (+`?force=1` на видалення), CRUD `/questions`

(валідація всіх рядків, вставка «все або нічого», помилки з номерами рядків).

### Вибір категорії у грі

```
Дисплей → меню «ГРАТИ» → модалка «Оберіть категорію» (fetch /api/categories)
  → createRoom { categoryId }  (сервер зберігає room.categoryId)
  → лобі → адмін тисне «Розпочати гру» → startIntro
       сервер перевіряє categoryReadiness(room.categoryId):
         < 9 активних питань → emit "gameError" «У цій категорії недостатньо питань для гри.»
  → phases.startGame → questions.getRounds(categoryId):
       усі активні питання категорії → crypto-shuffle → перші 9
       для кожного: crypto-shuffle 4 відповідей, correctIndex = нова позиція правильної
```

Кожна гра рандомізує **і** набір з 9 питань, **і** порядок відповідей. Правильність
рахується лише сервером за індексом після перемішування — ніколи за візуальною
позицією. Питання з інших категорій у гру не потрапляють; вимкнені питання й
вимкнені категорії — теж.

## Пауза (адмін)

Адмін (перший гравець) має на телефоні кнопку ⏸ з моменту старту інтро до кінця гри.

- **Сервер** — `server/clock.js`: у кожної кімнати свій ігровий годинник `now(room)` і таймери
  `schedule/cancel`, які на паузі заморожуються й потім продовжують з тим, що лишилось. Усі
  таймери фаз, міні-ігор і фіналу йдуть через нього; часові мітки для клієнтів — у ігровому часі.
  Події `pauseGame` / `resumeGame` (лише адмін) → `gamePaused` / `gameResumed`. Ігрові події,
  що прийшли під час паузи (Done-рукостискання дисплея, відповіді, дії в міні-іграх), стають у
  чергу `room.deferredWhilePaused` і виконуються після продовження.
- **Клієнт** — `client/src/game/gameClock.js`: ігрові `now/setTimeout/setInterval`, які стоять на
  паузі (їх використовують `App.js` і всі компоненти гри). На паузі дисплей також зупиняє всі
  відео/аудіо та CSS-анімації (`html.game-paused`); екран — `components/PauseOverlay.jsx`.

## Складність гри

Обирається разом із категорією в меню телевізора (`createRoom { categoryId, difficulty }`,
`room.difficulty`): «Легка» / «Середня» / «Складна» / «Наростаюча» (`mixed`: раунди 1–3 легкі,
4–6 середні, 7–9 складні). `questions.pickRoundsByDifficulty` бере для кожного раунду випадкове
питання потрібної складності, а коли їх бракує — найближчої (`easy→medium→hard`, `hard→medium→easy`);
питання без складності вважаються середніми. Гра стартує з будь-якою складністю, якщо в категорії
≥ 9 питань загалом.

## Життя, привиди, рейтинг

- Життя знімає лише `applyMinigameLives`. На 0 гравець отримує `isGhost: true` (`diedAtRound`).
- **Привид** далі відповідає на питання вікторини і отримує **половину балів** (`GHOST_SCORE_SHARE`,
  округлення вгору): усі зміни `score` ідуть через `awardScore()` у `phases.js`.
- **Хто грає міні-ігри:** якщо живих ≤ 4 (`SMALL_GAME_MAX_PLAYERS`) — **усі живі**, але життя
  втрачає лише той, хто програв міні-гру **і** помилився в раунді (`mg.protectedIds` — ті, хто
  відповів правильно); бали за міні-гру нараховуються за реальним результатом. Якщо живих > 4 —
  грають лише ті, хто помилився. Міні-гра буває, тільки якщо хтось помилився.
- Привиди **не грають у міні-ігри** (`armMinigame` бере лише живих); якщо живих < 2 — міні-гри немає.
- **Рейтинг сумує все:** +10 за правильну відповідь вікторини (`SCORE_CORRECT`), а після кожної
  міні-гри — **+10** її переможцю (`MINIGAME_WIN_BONUS`, `resolveWinner`: КНП — останній, хто
  вижив; Тупоматика — найбільше балів, …) і **+5** кожному іншому учаснику, що зберіг життя
  (`MINIGAME_SAFE_POINTS`); хто втратив життя — 0. Нараховує `applyMinigameLives`, один раз.

## Фінальна гонка

Правила — чисті функції `server/finalBattle.js` (тести `finalBattle.test.js`), оркестрація й
таймери — `phases.js` (тести `phases.test.js`), константи — `config.js → FINAL`.

- Беруть участь **усі** (живі й привиди). Старт — за рейтингом **відносно лідера**
  (`finalBattle.startPosition(score, best)`): лідер — на середині доріжки (`FINAL.START_MAX` = 15),
  0 балів — найближче до тіні (`FINAL.START_MIN` = 6), решта пропорційно (половина балів лідера —
  посередині між ними). Далі середини не стартує ніхто, тож лідерові ще треба позмагатися.
- Кожне питання 10с, 4 варіанти. Перші три **правильні** відповіді за порядком надходження на
  сервер (лічильник `seq`, не клієнтський час) — +4/+3/+2 (`FINAL.MOVES`), кожна наступна
  правильна — +1 (`FINAL.MOVE_OTHER_CORRECT`), тобто 4-3-2-1-1-1-1. Кап на клітинці 30.
- Хто дійшов до 30 — переміг (кілька в одному кроці → найменший `seq`). Рівно один переможець.
- Тінь стартує зі смуги 2: 2 питання стоїть, далі +2, з 7-го питання +3 (`FINAL.DARKNESS`,
  підібрано симуляціями: фінал триває в середньому 7–9 питань, 90% ігор — до 9–11).
  `pos ≤ darkness` → `consumed`. На 13-му питанні тінь проходить вихід, тож гонка скінченна;
  всі поглинені → кінцівка `all_consumed`. На дисплеї зала поділена на 31 смугу (0–30).
- Питання фіналу — з тієї ж категорії, спершу незіграні (короткі першими), потім повтори.
- Від'єднаний гравець не блокує крок; темрява зрештою його забирає.
- Стадії: `intro` (Done + серверний fallback 30с) → `question` → `reveal` (4.5с) → … → `done`
  (сцена переможця 11с) → `gameFinished { winnerId, ending, standings }` → титри на дисплеї.
- Демо фіналу без 9 раундів: сервер з `FINAL_DEMO=1` приймає `debugStartFinal` з лобі.

## Відомі місця для роботи далі

- `round10.json` більше не використовується (раундів 9). Можна видалити або
  перенести питання в інші раунди.

- Коди кімнат 0000-9999 — маленький простір, вгадувані (тепер хоча б `crypto`).
